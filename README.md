# 希翎 ZU27DR 星座图上位机

本仓库保存 ZU27DR FPGA 板卡的 MATLAB 上位机程序，用于实时显示星座图和链路指标，并记录逐包指标与全部 I/Q 星座点。仓库不包含 FPGA 逻辑或固件。

## 文件

- `WPR_Metrics_GUI.m`：推荐的单文件入口，显示星座图、EVM、PER 及推算 BER 的 95% 上限、MER 和 Rx IF Power，并保存采集记录。
- `WPR_Metrics_Preview.m`：无需连接板卡的界面预览，使用模拟数据展示停止后的命名与保存操作。
- `WPR_GUI.m`、`WPR_GUI.fig`：旧版 GUIDE 界面，仍可独立运行；它的星座点记录与新程序分开。
- `proc_udp1.m`：UDP 数据接收、界面更新、星座点记录。
- `Handshaking.json`、`Constellation.json`：握手和星座数据请求。
- `int2asc2.m`、`parse_json.m`：通信帧辅助函数。
- `Log_UESTC.jpg`：主界面使用的图片资源。
- `tests/test_WPR_Metrics_GUI.m`：三种调制的离线回归测试。

## 运行

需要 MATLAB R2023b、Communications Toolbox 和支持旧版 UDP `udp` 对象接口的 Instrument Control Toolbox。将 MATLAB 当前文件夹切换到本仓库目录，在命令窗口运行推荐入口：

```matlab
WPR_Metrics_GUI
```

没有连接板卡时，先关闭已打开的采集窗口，再运行 `WPR_Metrics_Preview`。程序不会创建 UDP 对象，直接显示模拟采集停止后的星座图、曲线、浅黄色名称输入框和橙色 SAVE，可填写名称、试用保存。窗口和星座图均标注模拟数据，试存的 MAT 与 PNG 放在 `过程文件/界面离线预览/`，不进入正式采集目录；预览中的 START 和 Apply IP 不连接设备。查看后关闭预览，再运行 `WPR_Metrics_GUI` 进行正式采集。

界面顶部的 `Board IP` 用于输入板卡地址，端口固定为 `5001`。首次启动默认 `192.168.0.27`；点击 `Apply IP` 后，地址保存在当前电脑的 MATLAB 偏好设置中，下次启动会自动恢复。偏好设置按电脑本地保存，不会同步进 Git；另一台电脑可以独立使用 `192.168.0.28`。

左上角可单选 `QPSK`、`8PSK` 或 `16QAM`，每次重新打开界面默认 QPSK。选择后会更新红色参考点、星座图标题及 EVM/MER 的计算依据，并清空上一轮的屏幕数据。板卡调制仍按原有方式设置，采集前应让 GUI 选择与板卡实际调制一致。

顶部的“文件名称”可填写实验名称，支持中文，前后空白会去除；留空时显示灰色提示“输入要保存的文件名称，留空自动命名”，提示文字不会作为名称保存。采集前或 STOP 后均可修改，采集及保存期间锁定。点击 SAVE 时采用输入框的当前内容，保存后保留供下一轮使用；重新打开程序时为空。不增加命名弹窗或第二种保存方式。

确认 IP 和调制后，按以下方式操作：

1. `START` 开始请求，先预读一次板卡累计计数作为起点；下一份有效数据作为第 1 次正式更新，此时即可显示新增包数。正式更新的完整数据暂存在 MATLAB 内存中，此时不生成采集文件。采集期间锁定调制、IP 和 `START`；每轮固定使用一种调制。
2. `STOP` 停止通信并保留本轮数据，不自动保存。有有效数据时，`SAVE` 和“文件名称”标签变为橙色，名称输入框背景变为浅黄色，状态栏提示本轮数据未保存；没有有效数据时，`SAVE` 灰色禁用，名称区域不高亮。
3. 需要保留本轮结果时点击 `SAVE`，写出一个 MAT 数据文件和一张 PNG；全部成功后，`SAVE` 恢复灰色禁用，名称输入框恢复白色。保存期间锁定操作，完成后才能再次 `START`；失败时保留内存缓存，恢复名称区域高亮和 `SAVE`，可修改名称或重试。

再次 `START` 会直接清空上一轮缓存和计数起点，关闭窗口也会释放缓存，均不弹确认框、不自动保存。程序没有保存勾选框。请在新一轮采集前保存需要保留的结果。PER 和推算 BER 上限曲线显示本轮全部正式更新，其他曲线显示最近 50 次更新；内存记录保留全部正式更新及其 I/Q 点，不设固定点数上限，长时间采集会持续占用内存。

每条指标曲线的标题和当前值紧贴曲线排列。`PER · 95% 上限` 和 `推算 BER · 95% 上限` 相邻显示，PER 下方显示本轮错包/收包数。星座图下方用上下两行显示“数据更新：×× 次”和“本次新增：×× 包”，每收到一份正式更新就刷新。预读只建立起点，不计入更新次数，也不显示、保存其星座点或计算 EVM/MER。第 1 次正式更新的新增包数为当前 `pac_rx_cnt` 减去预读起点，后续为相邻更新的计数差；无新增时显示 0，计数回退或差值无效时显示 `--`。同一区域保留星座点数和时长；Tx/Rx、CRC 计数归在“板卡累计”一组。图表保留网格、坐标轴和边框；PER 与 BER 上限各自标示完整采集时间，其余曲线显示最近 50 次更新。计算口径说明放在对应控件的悬停提示中。

PER 采用单侧 95% Clopper-Pearson 二项分布置信上限，同时保留观测值 `per = K/N`。`N` 沿用预读起点之后板卡 `pac_rx_cnt` 的累计增量，`K` 为 `pac_rx_crc_err_cnt` 的累计增量；两个计数采用同一份预读起点，每次 START 重置。起点是 START 后收到预读数据的时刻，不能追溯按下 START 瞬间的计数，也不计入起点之前的历史累计值。这里的统计总包数不是 GUI 收到的 UDP 报告数量，也不是星座点数量；`pac_rx_cnt` 是否包含全部参与 CRC 判决的正确和错误业务包，仍需实验室按板卡协议核实，元数据明确记录该口径尚未验证。

预读完成、尚无正式更新时，两项上限显示 `--`；正式更新仍无新增统计包（`N=0`）时也显示 `--`，MAT 对相应指标保留 `NaN`。有样本但零错包时，观测 PER 为 0，95% 上限为 `1 - 0.05^(1/N)`，大样本下约为 `3/N`；有错包时按一般二项分布计算，全部错包时上限为 1。统计包数持续增加且没有新增错包时上限下降；新增错包可能使其上升，计数不变时也不会因等待而下降。错包数大于总包数等不合法计数显示“计数异常”，概率无效，本轮统计包数和错误包数仍保留供检查。

该上限以各包独立、同一轮测试错误概率稳定为假设；95% 是每个固定累计样本数下的单侧置信水平，不提供连续观察后择时停止的全程覆盖保证。零错误上限的下降表示统计证据增加，不表示链路性能随时间改善。

三种模式的参考星座均为单位平均功率，软件默认参数如下：

| 调制 | 参考星座 | 相位约定 |
| --- | --- | --- |
| QPSK | 沿用原 QAM-4 四点参考，I/Q 均为 `±1/sqrt(2)` | 四点位于 45°、135°、225°、315° |
| 8PSK | 单位圆上等间隔八点 | 默认偏置 22.5°，相邻点间隔 45° |
| 16QAM | 标准方形十六点，I/Q 电平为 `[-3,-1,1,3]/sqrt(10)` | 方形星座不额外旋转 |

三种模式统一沿用 `I/Q / (150 * sqrt(2))` 换算，原始点完整保留，不做逐包幅度或相位拟合。切换调制及每次 `START` 都重新创建 EVM/MER 计算对象，各包按当前参考星座计算指标。上述幅度和相位是软件默认值，须经实板参考点重合检查后，才能确认 EVM/MER 的测量有效性。

推算 BER 95% 上限由 PER 95% 上限按 `1 - (1 - PER上限)^(1/108000)` 换算，计算时使用数值稳定的等价公式。该换算假设固定包长为 `108000` bit、比特独立且等概率出错、任意比特错误导致错包；它不是直接测得的 BER，这些假设与板卡统计口径仍需实验核实。为兼容旧文件读取方式，MAT 继续保留由观测 PER 推算的 `ber_estimate`。板卡返回的 `rms` 保留标注为 `Rx IF Power`，不将其解释为 RSSI。

旧版 GUIDE 程序仍可按原方式运行：

```matlab
WPR_GUI
```

## 采集文件

停止后点击 `SAVE`，程序才会在 `constellation_records/` 下创建本轮文件夹。名称留空时为 `constellation_年月日_时分秒`；填写后为 `文件名称_本轮调制_年月日_时分秒`，例如 `103GHz_正向_衰减10dB_QPSK_20261110_143025`。时间均取本轮 START 时间，调制取已停止的这一轮，不受之后切换配置或延迟保存影响。重名时追加 `_1`、`_2` 等序号，不覆盖已有路径；输入含文件名禁用字符时在状态栏提示，保留缓存，修改后可重试。

“文件名称”控制外层文件夹名称，内部仍只保存以下两个文件：

- `metrics_recording.mat`：MAT v7.3 文件，使用普通结构体、数值数组和字符保存数据，包含星座点、逐包指标和采集信息三部分。MATLAB 可直接 `load`，没有 MATLAB 的电脑可用 Python `h5py` 自动读取。
- `dashboard.png`：STOP 时固定在内存中的界面图像，包含当时的调制选择、曲线和实时数值。

MAT 内部结构如下，`format_version` 为 `1`：

| 变量 | 内容 |
| --- | --- |
| `constellationPoints` | `i_raw`、`q_raw` 保存全部原始 I/Q 数值；`packet_start_index` 和 `point_count` 分别记录每份 UDP 报告的起始下标和点数。起始下标从 1 开始，第 k 项对应 `packetMetrics` 的第 k 份报告。 |
| `packetMetrics` | 正式更新序号（沿用字段名 `packet_number`）、接收时间、采集后的秒数、Tx/Rx 和 CRC 原始累计计数、本次新增包数 `rx_packet_increment`、EVM RMS、MER、Rx IF Power、观测 PER、PER 95% 单侧上限、本轮统计包数、错误包数、原有 BER 估算值，以及 `ber_upper_95`，各字段按正式更新排列。新增包数不可用时为 `NaN`。 |
| `metadata` | 格式版本、输入的名称前缀 `file_name_prefix`、实际保存文件夹名 `record_folder_name`、IP/端口、调制名称与阶数、参考星座、起止时间、时长、正式更新数和点数、I/Q 换算除数、预读起点 `counter_baseline`（四项原始累计计数和接收时间）、新增包数定义、PER 统计方法与假设、待核实的板卡计数定义、BER 换算假设和接收时间定义。 |

I/Q 直接按数组保存，不经过 JSON 或逐点表格转换，也不重复保存归一化点；归一化坐标由原始值除以 `metadata.normalization_divisor` 恢复。`NaN`、`Inf`、`-Inf` 保持原始数值含义。该格式没有 Excel 行数和单元格长度限制，实际采集规模仍受内存和磁盘容量影响。

时间戳是 MATLAB 电脑处理 UDP 接收事件的本地时间，`packetMetrics.receive_time` 是每行一份报告、精确到毫秒的字符矩阵。同一报告中的星座点共享该时间，不是 FPGA 的逐点时间戳。采集结束时间为 STOP 时间，不包含等待 SAVE 的时间。STOP 后修改下一轮的 IP 或调制，不影响已结束一轮的待保存数据与图像。零数据停止不生成采集文件。采集结果保留在本地，不纳入 Git。

MATLAB 读取一份报告中的全部点：

```matlab
data = load('metrics_recording.mat');
k = 1;
points = data.constellationPoints;
rows = points.packet_start_index(k) + (0:points.point_count(k)-1);
iq = (points.i_raw(rows) + 1i * points.q_raw(rows)) / data.metadata.normalization_divisor;
receivedAt = data.packetMetrics.receive_time(k, :);
perUpper95 = data.packetMetrics.per_upper_95(k);
newPackets = data.packetMetrics.rx_packet_increment(k);
```

Python 使用 `h5py` 读取同一份报告。HDF5 中 MATLAB 数组的维度顺序相反，下面按一维数组和按列取时间字符处理：

```python
import h5py

with h5py.File('metrics_recording.mat', 'r') as data:
    points = data['constellationPoints']
    metrics = data['packetMetrics']
    k = 0
    start = int(points['packet_start_index'][()].reshape(-1)[k]) - 1
    count = int(points['point_count'][()].reshape(-1)[k])
    i = points['i_raw'][0, start:start + count]
    q = points['q_raw'][0, start:start + count]
    divisor = data['metadata/normalization_divisor'][()].item()
    iq = (i + 1j * q) / divisor
    received_at = ''.join(chr(int(c)) for c in metrics['receive_time'][:, k])
    per_upper_95 = metrics['per_upper_95'][()].reshape(-1)[k]
```
