# 希翎 ZU27DR 星座图上位机

本仓库保存 ZU27DR FPGA 板卡的 MATLAB 上位机程序，用于实时显示星座图和链路指标，并记录逐包指标与全部 I/Q 星座点。仓库不包含 FPGA 逻辑或固件。

## 文件

- `WPR_Metrics_GUI.m`：推荐的单文件入口，显示星座图、EVM、PER、BER 估算值、MER 和 Rx IF Power，并保存采集记录。
- `WPR_GUI.m`、`WPR_GUI.fig`：旧版 GUIDE 界面，仍可独立运行；它的星座点记录与新程序分开。
- `proc_udp1.m`：UDP 数据接收、界面更新、星座点记录。
- `Handshaking.json`、`Constellation.json`：握手和星座数据请求。
- `int2asc2.m`、`parse_json.m`：通信帧辅助函数。
- `Log_UESTC.jpg`：主界面使用的图片资源。
- `tests/test_WPR_Metrics_GUI.m`：三种调制的离线回归测试。

## 运行

需要 MATLAB R2023b、Communications Toolbox 和支持旧版 UDP `udp` 对象接口的 Instrument Control Toolbox。将 MATLAB 当前文件夹切换到本仓库目录，在命令窗口运行推荐入口：

```matlab
WPR_Metrics_GUI
```

界面顶部的 `Board IP` 用于输入板卡地址，端口固定为 `5001`。首次启动默认 `192.168.0.27`；点击 `Apply IP` 后，地址保存在当前电脑的 MATLAB 偏好设置中，下次启动会自动恢复。偏好设置按电脑本地保存，不会同步进 Git；另一台电脑可以独立使用 `192.168.0.28`。

左上角可单选 `QPSK`、`8PSK` 或 `16QAM`，每次重新打开界面默认 QPSK。选择后会更新红色参考点、星座图标题及 EVM/MER 的计算依据，并清空上一轮的屏幕数据。板卡调制仍按原有方式设置，采集前应让 GUI 选择与板卡实际调制一致。

确认 IP 和调制后，按以下方式操作：

1. `START` 开始请求和采集，完整数据暂存在 MATLAB 内存中，此时不生成采集文件。采集期间锁定调制、IP 和 `START`；每轮固定使用一种调制。
2. `STOP` 停止通信并保留本轮数据，不自动保存。有有效数据时，`SAVE` 变为橙色，状态栏提示本轮数据未保存；没有有效数据时，`SAVE` 灰色禁用。
3. 需要保留本轮结果时点击 `SAVE`，写出一个 Excel 工作簿和一张 PNG；全部成功后，`SAVE` 恢复灰色禁用。保存期间锁定操作；失败时保留内存缓存，恢复 `SAVE`，可重试。

再次 `START` 会直接清空上一轮缓存，关闭窗口也会释放缓存，均不弹确认框、不自动保存。程序没有保存勾选框。请在新一轮采集前保存需要保留的结果。图表显示最近 50 个数据包，内存记录保留本轮全部有效包和全部 I/Q 点，不设固定点数上限；长时间采集会持续占用内存。

每条指标曲线的标题和当前值紧贴曲线排列。PER 主数值和曲线标为 `PER 95% 上限`，其下简洁显示观测 PER 及本轮错包/收包数。星座图下方显示 UDP 报告数、星座点数和时长；Tx/Rx、CRC 计数归在“板卡累计”一组。图表保留网格、坐标轴和边框，右侧趋势图共用时间刻度；计算口径说明放在对应控件的悬停提示中。

PER 采用单侧 95% Clopper-Pearson 二项分布置信上限，同时保留观测值 `per = K/N`。`N` 沿用每轮首个有效报告之后板卡 `pac_rx_cnt` 的累计增量，`K` 为 `pac_rx_crc_err_cnt` 的累计增量；每次 START 重置。这里的统计总包数不是 GUI 收到的 UDP 报告数量，也不是星座点数量；`pac_rx_cnt` 是否包含全部参与 CRC 判决的正确和错误业务包，仍需实验室按板卡协议核实，元数据明确记录该口径尚未验证。

首个报告仅建立基准，`N=0` 时 PER 上限、观测 PER 和 BER 估算值均显示 `--`，内存记录为 `NaN`，导出表格中的相应单元格留空。有样本但零错包时，观测 PER 为 0，95% 上限为 `1 - 0.05^(1/N)`，大样本下约为 `3/N`；有错包时按一般二项分布计算，全部错包时上限为 1。统计包数持续增加且没有新增错包时上限下降；新增错包可能使其上升，计数不变时也不会因等待而下降。错包数大于总包数等不合法计数显示“计数异常”，概率无效，本轮统计包数和错误包数仍保留供检查。

该上限以各包独立、同一轮测试错误概率稳定为假设；95% 是每个固定累计样本数下的单侧置信水平，不提供连续观察后择时停止的全程覆盖保证。零错误上限的下降表示统计证据增加，不表示链路性能随时间改善。

三种模式的参考星座均为单位平均功率，软件默认参数如下：

| 调制 | 参考星座 | 相位约定 |
| --- | --- | --- |
| QPSK | 沿用原 QAM-4 四点参考，I/Q 均为 `±1/sqrt(2)` | 四点位于 45°、135°、225°、315° |
| 8PSK | 单位圆上等间隔八点 | 默认偏置 22.5°，相邻点间隔 45° |
| 16QAM | 标准方形十六点，I/Q 电平为 `[-3,-1,1,3]/sqrt(10)` | 方形星座不额外旋转 |

三种模式统一沿用 `I/Q / (150 * sqrt(2))` 换算，原始点完整保留，不做逐包幅度或相位拟合。切换调制及每次 `START` 都重新创建 EVM/MER 计算对象，各包按当前参考星座计算指标。上述幅度和相位是软件默认值，须经实板参考点重合检查后，才能确认 EVM/MER 的测量有效性。

BER 按 `108000` bit 包长从观测 PER 推算，继续标为估算值，不使用 PER 置信上限代入。该换算假设固定包长、比特独立且等概率出错、任意比特错误导致错包，不能代替实际误码计数。板卡返回的 `rms` 保留标注为 `Rx IF Power`，不将其解释为 RSSI。

旧版 GUIDE 程序仍可按原方式运行：

```matlab
WPR_GUI
```

## 采集文件

停止后点击 `SAVE`，程序才会在 `constellation_records/constellation_年月日_时分秒/` 下保存：

- `metrics_recording.xlsx`：可直接用 Excel 或其他表格工具查看，包含三张工作表，顺序固定为“星座点”“逐包指标”“采集信息”。“星座点”每行一个 UDP 报告，含包号、接收时间、点数以及 JSON 格式的原始 I/Q 数组；数组下标就是包内点号，归一化坐标可按采集信息中的换算除数还原。“逐包指标”每行一个 UDP 报告，含包号、接收时间、EVM RMS、MER、Rx IF Power、PER 95% 单侧上限、本轮统计包数、错误包数和 BER 估算值。“采集信息”记录 IP、调制方式、参考星座、起止时间、I/Q 换算、PER 统计方法与计数口径、BER 换算假设和接收时间定义。
- `dashboard.png`：STOP 时固定在内存中的界面图像，包含当时的调制选择、曲线和实时数值。

每张数据表最多容纳 1,048,575 行数据，另留一行表头。现在“星座点”按 UDP 报告存行，点数增长不会直接变成 Excel 行数；只有 UDP 报告数超过上限时才追加“星座点_2”等续表。单个 I/Q JSON 数组受 Excel 单元格 32767 字符限制，程序超出时会报错并保留缓存，避免静默截断。

正常数值保存为数字；不可用的 `NaN` 留空，正负无穷大分别保存为文本 `Inf`、`-Inf`，含义记录在“采集信息”中。I/Q 数组使用 JSON 数字数组保存，自动读取时解析 `i_raw_array` 和 `q_raw_array`，再按数组下标恢复点号；同一行的接收时间适用于数组中的全部点。观测 PER 可由逐包指标中的本轮错误包数除以统计包数还原，统计包数为零或计数异常时无有效结果；板卡原始累计计数不再重复导出。

时间戳是 MATLAB 电脑处理 UDP 接收事件的时间，工作簿中保留到毫秒；同一包中的星座点共用该时间，不是 FPGA 对每个采样点分别打的时间戳。采集结束时间为 STOP 时间，采集时长可由起止时间计算，不包含等待 SAVE 的时间。STOP 后可修改下一轮的 IP 或调制；待保存记录和图像仍对应已结束的一轮，直到保存成功或再次 START。零数据停止不生成采集文件。采集结果保留在本地，不纳入 Git。

## 验证状态

2026-11-08，MATLAB R2023b 下的离线回归覆盖三种参考星座与已知误差下的 EVM/MER、重复采集时 PER 和缓存重置、START/STOP/关闭窗口不生成采集文件、有数据时 SAVE 高亮、零数据时禁用、采集和保存期间的操作锁定，以及 JSON 数组的完整读回。

PER 检查覆盖零错包的精确上限、非零错包时通过独立二项分布累积概率核对置信上限、全部错包情况、无新增业务包时上限不变，以及不合法计数显示与记录。首个报告没有累计样本时显示 `--`；BER 继续使用观测 PER 推算。置信上限、统计总包数、错误包数和置信方法已核对工作簿与内存记录的一致性。

手动保存检查包括工作簿三张表的顺序、精简字段和数据完整性、停止后切换 IP/调制再延迟保存、PNG 与停止时内存图像逐像素一致，以及目录不可写和图像写入失败后的缓存保留与重试。已在 1480×900、1200×760 两种窗口尺寸检查文字控件边界，并回看生成的界面图像；三种调制连续切换后，截图的单选状态、标题与保存数据一致。此前已验证 IP 偏好设置恢复；本轮回归保持本机偏好设置不变。

本轮新增检查将每张数据表临时限制为 3 行，验证续表的顺序、编号及 JSON 数组完整性；另验证 `NaN`、`Inf`、`-Inf` 的导出和读回，修正 MATLAB 默认把正负无穷大写成 `65535` 的行为。工作簿使用 MATLAB 内置写入方式，不需要启动 Excel；也已使用 Python 独立读回核对工作表、字段和特殊值。

同日用本机合成的 138.75 万个点做了保存格式基准。旧的逐点 Excel 表约 167 秒、约 45.4 MB；改为每个 UDP 报告一行、I/Q 用 JSON 数组后，2775 个报告的 MAT 保存约 3.05 秒，Excel 工作簿约 30.12 秒、约 25.8 MB。两组数据的点数和数值序列一致；该结果只反映当前电脑、磁盘和合成数据，实板数据及其他电脑的耗时会变化。自动分析按报告行读取工作簿，需要逐点数据时再解码对应的 JSON 数组，不需要逐点展开后再保存。

主程序代码检查未发现语法错误，通信继续保留带弃用提示的 `udp` 接口。当前界面截图使用 R2023b 的 `print -RGBImage`；该版本仍包含 UI 控件，同时提示未来版本可能调整此行为，升级 MATLAB 时需重新核对截图。实板验收仍待实验室进行。

另对三种调制的历史 MAT 各取 10 包，共 15000 点做只读辅助检查，重算指标与独立的最近参考点计算一致，源文件 SHA-256 校验保持不变。历史文件的调制名称及原存指标不能单独证明当前默认幅度、相位已标定。`.27` 与 `.28` 板卡的调制支持、参考点匹配、实时曲线及保存结果仍待实验环境分别核对；本机回环、合成数据和历史数据检查不代替实板验收。
